# Footer

The real footer with agent selection, context, scope, composer options and send/stop actions.

## Usage

Create one presentation adapter for the owning AgentUiController. Pass its panel and the same transcript state to the footer and body. blocked reflects pending host operations; documentActions receives the composer formatting snippet.

<Source code={Basic} language="tsx" />

## Anatomy

| Part         | Responsibility                                          |
| ------------ | ------------------------------------------------------- |
| Actions      | Attachments, mentions and docked document formatting.   |
| Controls     | Agent picker, context usage and composer options.       |
| Workspace    | Current host-owned scope.                               |
| Send control | Send, Queue or Stop derived from real controller state. |

## Behavior and accessibility

onSend requests submission. Stop invokes the host cancel action and waits for acknowledgement. Changing agents and scope uses advertised host choices. The footer does not own persistence, execution or controller disposal.

## Styling variables

## Composition

[Complete screens](?path=/docs/agent-complete-screens--docs) use these production
components with the same controller flow. Documentation shell previews are
bounded to 40rem; Canvas screens use the full viewport. Story data and simulated
host effects stay outside published packages.

Errors and warnings belong to `ChatMessageComposer.status`, also available as
`options.composer.status` on AgentTranscript. The fixed footer owns actions only
and never renders a duplicate banner. Pair standalone footer stories with the
shared composer to review feedback in both presentations.

Hosts with durable follow-up queues can set `transcriptOptions.queueWhileAwaitingApproval`
on AgentChatScreen. This retains the editor and exact permission controls in both
views, with a single Queue/Stop action. Typing never sends or approves implicitly.
Standalone footers receive the same boolean prop. The default permission-only
panel remains unchanged.
