# Agent permissions

Outlined requests show captured resources and commands, exact advertised decisions, and read-only acknowledged outcomes.

## Usage

Pass the exact host request and retain the controller for the owning session. Callbacks submit only explicit user choices. Host acknowledgement supplies the completed state; mounting never responds.

## Behavior and accessibility

The allowance menu changes the proposed option without dispatch. Only the explicit response button submits the exact advertised ID. Project/device scopes in this catalog are simulated host capabilities; allow-always never implies either scope on its own. Unknown options retain neutral labels. Submitting and unknown states block duplicate responses. Refused requests retain their chosen scope. Approved means permission was granted, not that execution succeeded. Timestamps are host-supplied; cancelled, unavailable and historical requests cannot dispatch.

## Composition

Complete Document and Classic chats use these same production components in their existing composer drawers. Acknowledged permissions appear as compact, collapsed transcript rows labelled with their outcome and request title. Expanding the row renders this same full card read-only, including captured resources, command and allowance. Denied labels and icons use readable red in both themes, and collapsed rows use the same compact trailing gap as tools. Denials remain distinct from tool execution errors. Existing permission history remains visible while a later question is awaiting a response. Host adapters own permission enforcement, persistence and transport; this slice stops before Desktop and JJ Store adoption.
