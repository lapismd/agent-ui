# Composer drawer

Supplementary attachment and request content above the message editor, copied from Desktop.

## Usage

Use the drawer with the presentation adapter from the owning chat controller. Document mode renders the open disclosure above the writing surface; framed mode belongs in the composer drawer slot. Keep primary send and stop actions in the footer so collapsing the drawer never hides them.

<Source code={Basic} language="tsx" />

## Anatomy

| Part              | Responsibility                                               |
| ----------------- | ------------------------------------------------------------ |
| Root surface      | Supplementary content beside the controlled editor.          |
| Disclosure toggle | Named keyboard and pointer collapse control with item count. |
| Pending request   | Approval or question using exact host request identities.    |
| Files             | Host-supplied attachments with explicit removal controls.    |

## Behavior and accessibility

The disclosure label changes between Attachments, Permission requested and User input requested. Collapsed content is removed from keyboard navigation. Removing a file changes the host-owned attachment selection; answering a request sends only the exact advertised identity and answer.

The documentation follows the Usage, Anatomy and Examples pattern in [Astryx Chat Composer Drawer](https://astryx.atmeta.com/components/ChatComposerDrawer), using this package’s Svelte APIs and the existing Desktop visuals.
