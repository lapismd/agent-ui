# Transcript

The shared production transcript body, composer, attachments, message queue and send feedback.

## Usage

Use the same AgentUiController and presentation adapter as AgentChatScreen. Keep that controller owned by the host across presentation changes. AgentChatScreen composes this component, so a fix here also fixes complete screens.

<Source code={Basic} language="tsx" />

## Anatomy

| Part               | Responsibility                                                              |
| ------------------ | --------------------------------------------------------------------------- |
| Captured items     | Immutable host messages, context, reasoning, tool activity and handoffs.    |
| Block readers      | Markdown, code, patches, context and custom blocks.                         |
| Inline review      | Exact-range draft and published comments on captured source.                |
| Composer and queue | Retained authored draft, pending comments, waiting follow-ups and feedback. |

### Portable reference and action review

Complete Chat reference stories use this same production Transcript and composer.
The host's `composer.references` codec reaches Markdown previews, retained readers
and inline comment editors. `composer.referenceSources` supplies suggestions;
additional editor and preview extensions remain independent public hooks.
Person/agent chips share jj-store's inline styling. Optional
`references.getPopover(reference)` supplies host-owned profile content in preview,
transcript readers and composer. Only editable composers offer exact token removal.

`getMessageActions(messageId, block)` provides primary/overflow actions with
capabilities and disabled explanations; reactions remain host-owned. Comment is
icon-only. Wholly unavailable action bars are absent and invisible bars do not
intercept tool controls. `actionTooltips=false` removes tooltip content.

Use `AgentPort.resolveRecipients` only when the host explicitly derives recipients
from the exact submitted text. Without it, references never add recipients.
Unknown delivery retains the original request and resolved recipients.

Supply `new AgentUiController(port, initial, { canComment })` to control inline
comment admission without clearing retained drafts or changing reader controls.

## Behavior and accessibility

Document and Classic retain the same controller, source revisions and comment anchors. Tool inspectors share the exact readers. Unknown outcomes retain the pending request and do not replay it. The public options forward history, Markdown hooks, custom blocks, supplements, thread navigation, message actions and reactions; host authority remains explicit. Sent-comment editing is not enabled by this Agent adapter.

## Composition

[Complete screens](?path=/docs/agent-complete-screens--docs) use these production
components with the same controller flow. Documentation shell previews are
bounded to 40rem; Canvas screens use the full viewport. Story data and simulated
host effects stay outside published packages.

The full example reuses Desktop's sanitized 22-row recorded conversation (30 tools
and three simulated discussions), then adds Desktop-specific system/error,
local report, inventory, recipient and saved-turn surfaces. Sent context contains
the complete simulated ACP payload with the actual `lapis_context` and
`lapis-context` wire delimiters, separate from authored text.

Supply `options.messages` and explicit `onRetry`, `onCopyResponse`, `onOpenPath`
callbacks for host actions. `options.blocks` describes local result renderers;
`customBlock` remains the host's registered result-view hook. `icons` is a
presentation-only map, keeping component functions out of persisted snapshots.
`options.changes` integrates the saved-turn controller. Use
`options.composer.status` and `options.composer.statusPosition` for attached
warnings and errors; failed authored messages use
Design Core's `item.status` metadata below their body.

Refused sends stay in the editable draft. The shared MessageMetadata appears
immediately below that exact draft in both views. Editing the draft or changing sessions cannot attach the
previous refusal to another message. Unknown outcomes retain recovery feedback.
Document mode leaves 4rem below the composer (3rem below 600px), using the
document's original trailing buffer. Override
`--ui-transcript-composer-trailing-space` on the host to change it.

Acknowledged requests use `snapshot.requestResults`, keyed by the exact captured
custom block ID, or an `options.blocks` request presentation. Put each request
result in its own transcript item. The transcript projects it into its native
collapsed disclosure row, labelled with the host-observed outcome and request
title. Opening it shows the same full permission/question card read-only; mounting
or expanding cannot submit another response. Unknown responses keep their captured
request in the drawer until the host acknowledges them. Other completed history
remains visible during later requests. Hosts own capture order and persistence.

Active permission requests replace the message editor with the shared expandable
permission panel in the fixed footer area in both views. They remain visible while
history scrolls or new text streams. The panel shares the permission card's border,
radius and theme surface, with bounded details and attached error/warning feedback.
The controller retains drafts and comments; approving or denying restores the
editor without sending the draft. Each new permission opens its panel. Answer
requests retain their existing presentation.

The header Close control dismisses only the local permission prompt. The same
request stays dismissed across streamed snapshot refreshes and can be restored by
the host. New request identities appear normally. An unresolved submitted response
keeps its captured operation, warning and explicit Check original response action.

Editable inline comments place the T toggle at the far right, after the hover
actions on the same row. Hidden actions reserve no editor width. It opens the shared formatting actions
and emoji picker below the input, aligned with the text, and closes without
changing the draft or selection. Denied permission history uses a red label/icon and the shared compact
tool-row spacing, while retaining its captured permission outcome.

Use `status={{ type: "error", message: "The host refused this request." }}` or
`status={{ type: "warning", message: "Check the original request before continuing." }}`
on ChatMessageComposer; complete transcripts forward the same API through
`options.composer.status`. Host errors outrank advisory warnings. Unknown outcomes
remain warnings, and status rendering never retries or clears a draft. Fixed
action footers and keyboard hints do not render a second banner. The older
`sendError` and top-level `composerStatus` props are compatibility aliases.

Hosts with durable follow-up queues can set `transcriptOptions.queueWhileAwaitingApproval`
on AgentChatScreen. This retains the editor and exact permission controls in both
views, with a single Queue/Stop action. Typing never sends or approves implicitly.
Standalone footers receive the same boolean prop. The default permission-only
panel remains unchanged.
