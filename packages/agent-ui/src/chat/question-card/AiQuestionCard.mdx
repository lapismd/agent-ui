# Agent questions

Single-choice, multiple-choice and freeform requests using the same production controller and components as complete chat screens.

## Usage

Pass the exact host request and retain the controller for the owning session. Callbacks submit only explicit user choices. Host acknowledgement supplies the completed state; mounting never responds.

## Behavior and accessibility

Radio groups support arrow-key navigation; checkboxes support multiple answers. Fields have visible labels, optional descriptions and explicit required/disabled states. Letter badges (`A`, `B`, `C`…) are the default; numeric badges (`1`, `2`, `3`…) and no badges are optional. Badges are decorative, do not change the accessible choice name and never become answer values. When the host permits `allowOther`, an explicit Other row opens an editable answer, including for multiple choice; secret inputs are masked and their values never enter captured results. Request-scoped controller drafts survive refresh, remount and presentation/theme switches. Existing consumers keep label-based answers; an explicit host value overrides that label. Character limits apply only when advertised.

## Styling variables

Letter and number badges have a solid muted fill, similar to the card surface, using public Badge color tokens. The brand and light/dark controls use semantic Design Core themes. Override audited variables on an ancestor; no dependency selectors are needed. Docs shell previews remain bounded while Canvas screens retain the viewport.

## API

<ArgTypes of={Stories} />

`request.questions` declares each field's behavior:

| Field                | Default          | Purpose                                                        |
| -------------------- | ---------------- | -------------------------------------------------------------- |
| `optionLabels`       | `"letters"`      | Decorative `"letters"`, `"numbers"` or `"none"` choice badges. |
| `selectionMode`      | `"single"`       | Radios or `"multiple"` checkboxes.                             |
| `allowOther`         | Required         | Whether the host permits a completely different answer.        |
| `inputMode`          | `"text"`         | Single-line input or multiline `"textarea"`.                   |
| `placeholder`        | None             | Hint for freeform or Other input.                              |
| `required`           | `true`           | Whether an answer is required before submission.               |
| `secret`             | Required         | Mask input and exclude answer values from history.             |
| `maxLength`          | None             | Optional host limit for authored answers.                      |
| `showCharacterCount` | `false`          | Show a non-secret answer's length.                             |
| `options[].value`    | The option label | Exact host response value; selection retains `options[].id`.   |

## Composition

Complete Document and Classic chats use these same production components in their existing composer drawers. Completed request blocks reuse them read-only in the transcript. Host adapters own permission enforcement, persistence and transport; this slice stops before Desktop and JJ Store adoption.
