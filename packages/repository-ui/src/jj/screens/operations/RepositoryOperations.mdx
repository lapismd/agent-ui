# Op Log

Complete Desktop operation log, metadata comparison and changed-file inspector.

## Usage

Mount the complete Op Log with its independent host-owned OperationController. It composes the original graph and metadata/file inspector rather than sharing the JJ Log’s mutable selection.

<Source code={Basic} language="tsx" />

Enable `searchable` for the native operation metadata language. The controller
sends `operations_filtered` and retains the current operation pin; it does not
interpret commit revsets or implement indexed full-text search. Hosts may replace
the header controls to supply their own richer query editor and navigation.

## Behavior and accessibility

Header, operation, metadata, changed-file and diff snippets receive the complete
`OperationState`, including exact pin, parent, group, revision pair and path.
`onRevert` only requests a host action; hosts own admission, confirmation,
execution, pending state and feedback. Without it the original control remains
disabled. Controller construction issues no reads or mutations.

`OperationControllerOptions` is an optional fourth constructor argument; defaults
remain 50 operations per page and at most 200 displayed operations. Changed
revisions and paths retain their 500-item bounds with explicit status. Query
changes clear dependent selections, stale replies are discarded and invalid
continuations are reported through the injected feedback port. Workspace is
retained host navigation context, not an invented operation-query predicate.
More operations spans the entire row with a centered, muted label. The
`src/history/controller.ts` example retains a long unchanged section between
edits, exercising the shared diff reader's unmodified-line expansion controls.
The in-memory filter fixture demonstrates `description:"rebase"`, `none` and
`invalid`; it is not an implementation of the native query grammar.

Expanding a complete single-change operation selects that change and shows its files immediately. Multiple/paged changes require a choice from Revisions; ambiguous pairs require both endpoints. Selecting a file uses the same pinned handle. onHistory delegates the selected operation to host navigation. Keyboard focus, labelled controls and explicit retry actions follow the shared Design Core primitives.
