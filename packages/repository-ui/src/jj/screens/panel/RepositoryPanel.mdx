# JJ Log

Complete Desktop JJ Log AppShell and adaptive Column Canvas with an in-memory history controller.

## Usage

Mount the complete embedded JJ Log with a host-owned HistoryController and copy callback. Optional source and restore ports add the same controls used by Desktop.

## Anatomy

| Part        | Responsibility                                                        |
| ----------- | --------------------------------------------------------------------- |
| AppShell    | Original bounded embedded body and optional conflict surface.         |
| Log column  | Shared header, graph, revision details and file listing.              |
| Diff column | Shared diff reader, layout/wrap controls and optional restore dialog. |

## Behavior and accessibility

Mount reads through the injected controller. Host lifetime outlives pane remounts; initialOperation and initialRevision restore exact selections. Dispose the controller only after its final owner releases it. No native transport, routing or preference storage is constructed here. Keyboard focus, labelled controls and explicit retry actions follow the shared Design Core primitives.

Built-in search is opt-in with `searchable` and accepts native JJ revsets;
`HistoryController.search()` keeps the exact operation/workspace and clears
selected revision/file comparisons. Blank queries reset to `all()`. The host
supplies user email and an evaluation clock through `HistoryControllerOptions`;
paging retains that clock. Indexed/full-text search remains a host service and
can provide its own controls through `headerControls`.

Use `headerActions`, `headerControls`, `revisionActions`, `fileActions` and
`diffActions` for host-specific navigation, review and command controls. Snippets
receive the displayed selection context; rendering cannot execute an action.
The default source/workspace/pin/refresh controls remain when no replacement is
provided, and the shared column toggle always remains present.

## Styling variables

Complete screens compose this same implementation. Small controls use a padded, bounded standalone preview; shell and column families retain their required production context.
