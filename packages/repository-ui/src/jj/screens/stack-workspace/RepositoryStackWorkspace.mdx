# Stacks and Workspace

Source-adapted complete Stacks/Workspace AppShell with fixed lanes, original geometry, host-owned controllers and independent adjacent diffs.

## Usage

Use the host-retained StackWorkspaceController and exact recorded repository, operation, readKey and source identities. The host constructs, refreshes and closes its controller; rendering never calls preview/apply or mutates repositories. Timestamps and now are Unix seconds.

## Behavior and accessibility

The screen toolbar has no lower border. Target history uses the same 16px
branch icon size as the other column headers.

Column widths match JJ Store: Branches 320 (260–520), Unstaged 330 (260–520), stack/target lanes 390 (310–640) and diff 580 (360–980) pixels. Fixed leading columns, independent bodies, original graph rows, collapse and keyboard/pointer resizing remain shared primitives. Workspace uses applied topology, while Stacks shows the selected captured branch.

Selecting a branch aggregate or a commit reveals its exact files. File selections retain independent originating columns. Target history is read-only and never enters applied membership. Native conflict/binary/unloaded/empty states stay distinct. Supplied counts are preserved; unknown counts remain absent and folder totals describe loaded descendants.

Hosts provide copyText, optional onCommand/onSelectWorkspace and optional headerActions, columnActions, branchActions, commitActions, fileActions, diffActions and composer snippets. Actions receive recorded objects and do not select unrelated rows. Hosts own navigation, settings/persistence, notifications, preview/apply and controller lifetime. Composer slots can bind the existing per-workspace drafts. Full mutation dialogs and forge execution remain host responsibilities.

PR integration is optional. Hosts supply `pullRequests` (a retained
RepositoryPullRequestReview), `onPullRequestAction`, optional `onPushBranch`,
`onCreatePullRequest`, `onSubmitStack`, `onWorkspaceSettings` and `onCopyError`. Only matching
repository/revision/readKey/workspace records appear. PR-only selection opens
the same per-origin column as a later file selection; its PR card remains above
the embedded diff. Float/Dock retains the same content instance and drafts.
Workspace controls expose settings, create workspace/stack, Undo/Redo and
refresh; branch and commit bars use capability-aware typed host requests.

## Action wiring status

Git/JJ buttons call the supplied clipboard service. Stage/Start a commit requests call `onCommand` with a create-commit intent; the host must open its composer and handle admission. Native hunk checkboxes retain their exact tokens. Hunk assignment requests call the host only when transfer is admitted.

With `onCommand`, file/folder/hunk/commit drag sources and stack, branch, commit,
Unstaged and new-stack destinations use the existing drag session. Valid and
invalid guides reflect current capabilities; drop rechecks the live snapshot.
Preview/unknown-outcome locks block sources and destinations. Drag end or a
scope change clears feedback. The component emits a typed command with the
current snapshot; the host chooses preview, confirmation and execution.

The optional `composer` and action snippets remain host extension points.
Source-adapted branch/commit menus and a retained inline commit composer now
provide the ordinary workflow. Their callbacks request exact host commands;
presentation never previews or applies a mutation by itself.

## Composition

Complete Stacks/Workspace screens compose the same documented lanes, source files and independent diff columns. Small source-file examples use padded bounded pages; lanes/diffs retain their actual Column Canvas context. Override only public tokens or native root style props. RUI-STACK-001 governs this presentation review; stories remain visual-pending and broader checks wait for final review.
