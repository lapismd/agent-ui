# Workspace source files

Operation/read-key-pinned source listing with supplied file counts, cumulative loaded folder statistics, conflicts, paging and explicit selections.

## Usage

Use the host-retained StackWorkspaceController and exact recorded repository, operation, readKey and source identities. The host constructs, refreshes and closes its controller; rendering never calls preview/apply or mutates repositories. Timestamps and now are Unix seconds.

## Behavior and accessibility

Column widths match JJ Store: Branches 320 (260–520), Unstaged 330 (260–520), stack/target lanes 390 (310–640) and diff 580 (360–980) pixels. Fixed leading columns, independent bodies, original graph rows, collapse and keyboard/pointer resizing remain shared primitives. Workspace uses applied topology, while Stacks shows the selected captured branch.

Selecting a branch aggregate or a commit reveals its exact files. File selections retain independent originating columns. Target history is read-only and never enters applied membership. Native conflict/binary/unloaded/empty states stay distinct. Supplied counts are preserved; unknown counts remain absent and folder totals describe loaded descendants.

Hosts provide copyText, optional onCommand/onSelectWorkspace and optional headerActions, columnActions, branchActions, commitActions, fileActions, diffActions and composer snippets. Actions receive recorded objects and do not select unrelated rows. Hosts own navigation, settings/persistence, notifications, preview/apply and controller lifetime. Composer slots can bind the existing per-workspace drafts. Transfers, mutation dialogs and forge execution are outside this slice.
