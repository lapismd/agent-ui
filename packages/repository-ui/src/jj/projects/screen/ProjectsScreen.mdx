# ProjectsScreen

JJ Store's project and task directory, review discussion and linked repositories with independent metadata homes. The live source-composition gate remains open; this family is not yet accepted as complete.

## Usage

The host owns admission, snapshots, version checks, persistence and exact request receipts. Mount this complete screen inside the application Main. This minimal public example is deliberately read only; production hosts provide all supported actions through WorkPort.

## Behavior and accessibility

Construction and mounting never issue repository mutations. Hosts open and close the production controller. Home IDs are local admission identities; linked code references use separate portable IDs. Duplicate names never become identities. Global browsing does not select a code checkout. The host explicitly activates code only through onOpenRepository.

Directories request at most 25 rows per page and 20 homes per batch with four concurrent reads. Continuations retain snapshot identity and reject duplicates and stale replies. Partial failures preserve other homes and expose Retry. Unknown requests retain their exact payload and permit status inspection; refresh and mount never dispatch them. Native adapters must persist intent before execution.

Project and task rows retain source button hit areas and separate author controls. Forms have labels, retain drafts on cancellation/failure and focus restoration through the public Dialog. The contextual rail appears only for a selected project/task, using AppShell resizing and narrow-window presentation. Chat opens an explicit context through a callback and never sends automatically.

Projects, Tasks, Reviews and Repositories share one card/list button in both
global and selected-project views. Its icon, accessible name and tooltip show
the destination view; activating it retains keyboard focus.

## Composition

The host supplies optional `onCopyLink(route)` for canonical share links, `onOpenActivity(row)` for exact repository/operation/revision navigation and `copyText` for Git/JJ identifiers. `showRail` is bindable and defaults closed. Omitted task state means Active; `all` explicitly includes completed tasks.

Set `showHeader={false}` when an outer AppShell supplies ancestry/actions.
Set `showNavigation={false}` when the host supplies repository contextual tabs.
Both default to `true`. The complete screen retains its body and contextual rail.

Use public ProjectsController and WorkPort with the complete screen. Use header for host breadcrumbs and agents for a complete agent/session screen owned by its package. The packages do not import each other. The host owns repository activation, route ancestry, context chat, operational notification toasts and all credentials. Report unavailable capabilities explicitly. Actions/workflow pages are excluded; normal metadata controls remain functional.

Review pages consume optional `WorkReview.anchor`, `reviewRoot` and `context`.
The context contains a bounded, host-captured repository/operation comparison,
renderable file content and exact commit activity. Missing data is explicitly
unavailable; it never substitutes the active checkout. The files workbench uses
public Design Core listing and diff components, with filtering, split/unified
layout and local viewed marks. `onOpenActivity` receives the original commit
record. `copyText` also owns snapshot copying. Review replies use metadata-home
identity and the captured review version. Resolving hides an empty composer;
a retained draft stays visible. Thread connectors, reactions, inline review
annotations and comment continuation remain part of the pending discussion
slice, not claimed complete by this presentation pass.
