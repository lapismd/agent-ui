# Diff Viewer

A shared single-file or expandable collection of exact repository comparisons.

## Usage

The host owns the controller, comparison identity and preference persistence. Pass `diffFileMode` and `onDiffFileModeChange` to `RepositoryPanel` or `RepositoryOperations` to enable the column's All-in-one diff toggle. This standalone viewer receives the resulting `fileMode` and independent unified/split `viewMode`.

The complete-screen columns accept `getDiffStats(context)` for host-provided total
additions and deletions. The synchronous callback receives the exact operation,
from/to revisions and comparison key; return cached totals or `undefined`.
Totals cover every file, including unpaged files, and never fall back to the
selected file or a partial sum. Hosts own fetching, caching and invalidation;
replace reactive totals when the comparison changes. Zero totals remain visible.

## Behavior and accessibility

Disclosure buttons expose expanded state and controlled content IDs. Multiple files can stay open. Explicit selection expands and scrolls to the file; scrolling alone does not change selection. Repeat selection requests remain repeatable. Section state survives mode changes within one comparison and resets for new comparisons. Default batches contain 20 paths, with the existing 500-path cap shown explicitly. Content loads only for expanded sections, deduplicates pending requests and supports per-file retry. Binary and unavailable content remain distinct from empty changes.

`getDiffMenuItems(context)` provides commands, submenus and separators. Every command and submenu requires an icon. `RepositoryDiffActionContext` carries `comparisonKey`, operation, from/to, path and change for that section. Optional `createRepositoryDiffMenu` callbacks supply absolute-path resolution, clipboard and platform-specific reveal behavior. The helper omits unavailable capabilities. Custom async command failures are displayed locally; hosts may also report their own notifications. Menus use vertical kebabs and content-width popovers with single-line labels. The main menu sits immediately before Close and uses the same public Button hover shape. Menu controls do not toggle disclosure, and empty menus have no trigger.

Expandable sections configure the public Design Core tokens: `--ui-diff-frame-radius: 0px`, `--ui-diff-file-gap: 0`, `--ui-diff-file-section-border: 0` and `--ui-diff-file-section-separator: 1px solid var(--border)`. The collection is flush with its column by default (`--ui-repository-diff-viewer-scrollbar-inset: 0`); hosts may opt into an inset if needed. Expanded bodies use `--ui-diff-file-content-padding-bottom: 0` so the selection frame ends at the content. The selected file uses `--ui-diff-file-selection-outline: 1px solid var(--ring)` and `--ui-diff-file-selection-outline-offset: -1px` so all four edges stay inside the clipped column; its header inherits `--ui-diff-selected` through `--ui-diff-file-selected-header`, layered over an opaque Design Core diff surface so sticky content cannot show through. Header labels and status metadata form one keyboard-accessible disclosure button; the menu remains independent. File headers, syntax, changed rows, selected sections and gutters inherit the public Design Core diff tokens. RepositoryDiff owns rename provenance styles. No Mira or dependency-internal overrides are required.

## API

<ArgTypes of={Stories} />

Public companion exports: `RepositoryDiffMenu`, `createRepositoryDiffMenu`, `RepositoryDiffFileMode`, `RepositoryDiffPreferences`, `RepositoryDiffActionContext`, `RepositoryDiffMenuItem`, `RepositoryDiffMenuProvider`, `RepositoryDiffEntry` and `RepositoryDiffEntries`.

`RepositoryDiffComparisonContext` carries comparison identity without a selected
path, and `RepositoryDiffStats` carries complete additions/deletions. On the
complete screens, `diffActions` renders only in single-file headers;
`allChangesActions` provides comparison-wide header actions with the screen's
typed state. JJ Log's built-in restore moves to each file's menu in all-file
mode, using that section's exact path. Copy/reveal menus stay file-scoped.

## Composition

JJ Log and Op Log compose this same production viewer inside their original columns. Op Log retains operation metadata above the currently chosen revision-pair diff collection. Existing header action snippets remain available. Storybook uses disposable in-memory ports; native execution and downstream adoption remain behind review.
