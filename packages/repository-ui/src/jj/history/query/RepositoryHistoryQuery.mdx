# History query

The jj-store query editor adapted to a host-controlled shared component. Both log screens compose this same implementation.

## Usage

Pass the committed query and apply drafts through the owning controller. Hosts may supply `info` with native callable signatures, aliases, operators, operation fields and symbols; defaults offer common JJ vocabulary. Completion is lexical assistance; native validation stays host-owned.

## Anatomy

| Part              | Responsibility                                                                    |
| ----------------- | --------------------------------------------------------------------------------- |
| SearchFilterInput | Shared pill and CodeMirror custom-language editor.                                |
| Query actions     | Run query and disclose syntax/context.                                            |
| Completion        | Native vocabulary and snapshot bookmarks without transport or routing.            |
| Expanded help     | Source-style informational alerts, centered icons and language-specific guidance. |

## Behavior and accessibility

Ctrl/Cmd+Space opens completion, Tab accepts a suggestion, and Ctrl/Cmd+Enter applies the draft. Enter accepts active completion or applies when no completion is open. Strings suppress inappropriate suggestions. Query controls have accessible names; context disclosure retains focus and opens a labeled region with the same informational Alert composition as JJ Store. Language-specific guidance and host vocabulary share the public Design Core alert typography and semantic surface. Clearing restores all revisions or an unfiltered operation graph. Host validation, pins, errors and feedback remain in the existing controller.

## Composition

RepositoryPanel and RepositoryOperations bind the same query component to their own controller and derive bookmarks from the pinned snapshot. `queryInfo` replaces the default vocabulary when a host has richer native metadata. Neither editor performs native reads or mutations.
