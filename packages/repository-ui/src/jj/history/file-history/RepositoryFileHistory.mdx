# File history

Operation-pinned file history with date-grouped revision cards and host-owned navigation.

## Usage

Retain a FileHistoryController in the host and call follow with the active literal path. Mount this pane inside the public AppShell (or RepositoryShell) to browse only revisions that changed that file. The transparent AppShell.Toolbar matches the other shell headers. Pass onOpen to view this file at a revision and optional onBrowse to browse the repository at that revision; these callbacks never choose a new operation or perform a mutation.

| ------------- | -------------------------------------------------------------------------------------- |
| Header        | Transparent AppShell.Toolbar, active path, blame, refresh and optional host actions.   |

| Timeline      | Date headings group recorded commits without changing read order.                      |

## Behavior and accessibility

onOpen delegates the exact recorded revision for file code; onBrowse delegates that revision for repository navigation. It is absent when unsupported. onBlame requests host navigation. Wide cards separate metadata and actions with space-between; when actions wrap, they begin at the left edge of the next row. Description disclosure has an accessible name, expanded state and associated panel; clipboard and navigation controls are independent. Date groups use the recorded committer timestamp in UTC, while author metadata remains recorded author data. A missing active file, successful empty history and failed history have separate Empty states. The host closes the controller after unmounting all readers. Keyboard focus, labelled controls and explicit retry actions follow the shared Design Core primitives.

## API

Filename artwork comes from the public Design Core `FileTypeIcon`, resolved from the exact host path. Its `--ui-file-type-icon-size` override and `--ui-file-type-icon-size-xs`, `-s`, `-md` and `-lg` presets belong to Design Core; inherited defaults retain the original icon slots. See [File type icon](https://lapismd.github.io/design-core/?path=/docs/shadcn-data-file-type-icon--docs) for the complete styling contract.

## Composition

Complete screens compose this same implementation. Small controls use a padded, bounded standalone preview; shell and column families retain their required production context. Docs shell previews are bounded to 40rem and flush; Canvas screens fill their parent. Host services and downstream integration remain behind the review gate.
