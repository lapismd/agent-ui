# File history

Independent active-file pin, graph, explicit parent navigation and blame action.

## Usage

Retain a FileHistoryController in the host and call follow with the active literal path. Mount this independent pane to browse only revisions that changed that file.

<Source code={Basic} language="tsx" />

## Anatomy

| Part          | Responsibility                                               |
| ------------- | ------------------------------------------------------------ |
| Header        | Active path, blame action and explicit refresh.              |
| Pin           | Exact operation selector when a choice is required.          |
| History graph | Bounded file-specific revision list and continuation action. |

## Variations

### Basic

The ordinary populated presentation with recorded identities and explicit callbacks.

### Empty

A valid successful result with no content. The production component displays the shared Empty pattern with an icon.

<Canvas of={Stories.Empty} />

### Loading

A pending in-memory read holds the original loading geometry without contacting a repository.

<Canvas of={Stories.Loading} />

### Unavailable

A refused or failed read, distinct from a successful empty result. The production Empty state names the failure and leaves explicit recovery reachable.

<Canvas of={Stories.Unavailable} />

## Behavior and accessibility

onOpen delegates a recorded revision; onBlame requests host navigation. A missing active file, successful empty history and failed history have separate Empty states. The host closes the controller after unmounting all readers. Keyboard focus, labelled controls and explicit retry actions follow the shared Design Core primitives.

## Styling variables

## API

<ArgTypes of={Stories} />

Filename artwork comes from the public Design Core `FileTypeIcon`, resolved from the exact host path. Its `--ui-file-type-icon-size` override and `--ui-file-type-icon-size-xs`, `-s`, `-md` and `-lg` presets belong to Design Core; inherited defaults retain the original icon slots. See [File type icon](https://lapismd.github.io/design-core/?path=/docs/shadcn-data-file-type-icon--docs) for the complete styling contract.

## Composition

Complete screens compose this same implementation. Small controls use a padded, bounded standalone preview; shell and column families retain their required production context. Docs shell previews are bounded to 40rem and flush; Canvas screens fill their parent. Host services and downstream integration remain behind the review gate.
