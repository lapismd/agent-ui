# File Tree

Display loaded canonical files and directories using the public Design Core FileListing. The host retains the display mode, collapsed directories and selected file; expanding a directory can request its bounded page.

## Usage

Display loaded canonical files and directories using the public Design Core FileListing. The host retains the display mode, collapsed directories and selected file; expanding a directory can request its bounded page.

## Anatomy

| Part         | Responsibility                                                                               |
| ------------ | -------------------------------------------------------------------------------------------- |
| Tree heading | Shows the loaded file count and list/tree/package presentation control.                      |
| FileListing  | Owns icons, virtualized rows, controlled disclosure and selected-path presentation.          |
| Continuation | Requests another host-scoped page rather than fetching through a native client.              |
| Status       | Loading and empty content retain the production Skeleton and icon-bearing Empty composition. |

## Behavior and accessibility

The public FileListing owns keyboard navigation and disclosure. Tree, list and
package modes are controlled values; mode changes request the appropriate host
page scope. Directory disclosure requests only the disclosed path in tree mode.
Loading, empty and paged states do not imply that unloaded paths are absent.

## Composition

Place the file tree inside AppShell.Body.Sidebar, as RepositoryBrowser does.
Supply recorded paths and controlled disclosure state, then route file selection
through the pinned controller. Width persistence and the resize handle belong to
the enclosing screen, keeping the tree reusable in other layouts.
