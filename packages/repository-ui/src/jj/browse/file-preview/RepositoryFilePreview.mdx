# File Preview

Render an explicitly pinned recorded file. Text, binary, unavailable and successful empty content remain different states. The component requests history/blame/clipboard actions through the host and never edits or follows an external file system entry.

## Usage

## Anatomy

| Part            | Responsibility                                                                                  |
| --------------- | ----------------------------------------------------------------------------------------------- |
| Metadata        | Recorded author, commit/change identifiers and time use the existing shared history components. |
| File statistics | Host byte size and actual textual line count remain separate from availability.                 |
| File header     | Design Core FileTypeIcon, Preview/Source/Blame text toggles and optional host actions.          |
| Content         | Stock MarkdownContent and CodeBlock present the same text; code retains line numbers.           |
| Status          | Explicit binary/unavailable/empty presentation uses the same compact icon-bearing Empty.        |

## Behavior and accessibility

The source-adapted Preview, Source and Blame buttons expose the current view
through aria-pressed. Shadcn tooltips describe the header actions and semantic
hover surfaces provide feedback. Blame replaces the file contents in the same
card; the host supplies its pinned controller and content snippet. Markdown and source views render the same captured contents.
History, blame, clipboard and custom actions carry the explicit file selection.
Loading, refused reads, recorded unavailability, binary files and successful
empty text remain separate states; retry preserves the selected pin and path.
Short previews fit the available pane; only overflowing content scrolls through
the enclosing AppShell content region, without a second vertical scroll area.
