# Loading skeleton

Representative loading geometry for repository reads with accessible status.

## Usage

Use a skeleton while an injected read is pending. Choose geometry that matches the log, changed files, diff, file history, blame or conflict surface being prepared.

## Behavior and accessibility

Skeletons are presentational. The owning controller decides when preparation has completed or failed; an unavailable read must become an Empty state rather than an indefinite skeleton. Keyboard focus, labelled controls and explicit retry actions follow the shared Design Core primitives.

## Styling variables

Defaults retain the Desktop presentation. Set documented variables on an
ancestor; avoid selector overrides and dependency-internal imports. Brand and
light/dark controls remain independent in Storybook.
