# Blame

Recorded file text and virtualized attribution with controlled wrapping and pinned navigation.

## Usage

Retain a BlameController and open it with an exact operation, commit and path. This panel renders the recorded file beside attributed commit groups; it never computes attribution from the working copy.

<Source code={Basic} language="tsx" />

## Anatomy

| Part               | Responsibility                                                                 |
| ------------------ | ------------------------------------------------------------------------------ |
| Header             | Path, exact identifiers, controlled wrap and refresh.                          |
| Attribution gutter | Author avatar/name, commit subject/card and relative time.                     |
| Source track       | Virtualized syntax-highlighted source, stable line numbers and group dividers. |

## Behavior and accessibility

Source text and line numbers use Desktop’s 0.875rem (14px); attribution name/time use 0.75rem (12px). Long groups retain a sticky origin and large files remain virtualized. Bind wrap and persist it in the host through onWrapChange when desired. Commit hover cards expose statistics and onOpen delegates the exact commit ID. Keyboard focus, labelled controls and explicit retry actions follow the shared Design Core primitives.

## Styling variables

Defaults retain the Desktop presentation. Set documented variables on an
ancestor; avoid selector overrides and dependency-internal imports. Brand and
light/dark controls remain independent in Storybook.

## API

<ArgTypes of={Stories} />

Filename artwork comes from the public Design Core `FileTypeIcon`, resolved from the exact host path. Its `--ui-file-type-icon-size` override and `--ui-file-type-icon-size-xs`, `-s`, `-md` and `-lg` presets belong to Design Core; inherited defaults retain the original icon slots. See [File type icon](https://lapismd.github.io/design-core/?path=/docs/shadcn-data-file-type-icon--docs) for the complete styling contract.

## Composition

Complete screens compose this same implementation. Small controls use a padded, bounded standalone preview; shell and column families retain their required production context. Docs shell previews are bounded to 40rem and flush; Canvas screens fill their parent. Host services and downstream integration remain behind the review gate.
