# Governance

Component-family documentation is enforced by the repository-owned
`agentFoundations` validator plugin, loaded by the published spec-validator.
The inventory explicitly assigns private compound parts to documented families;
a new independent component requires its own colocated contract.
The `jjFoundations` plugin applies the same documentation, public-example and
token-default checks to the Desktop JJ inventory; deferred scaffolding MUST
remain frozen by exact hashes until its own extraction is reviewed.

The tracked AGENTS guide records the source-copy, per-family documentation,
token, controller and Storybook workflow for both packages; newly reviewed JJ
families MUST use the same fail-closed structure as Agent foundations.
The user approved the portable jj-store parity plan, beginning with chat
references and actions. Each section MUST stop for screen review. Iteration MUST
use targeted checks; broad qualification MUST wait until the final screen review.
Design Core owns generic fixes; application adoption and publication remain gated.

The next authorized section is JJ Log portability. Its optional host controls
MUST retain the original shell defaults, and its native revset examples MUST
remain distinct from host-owned indexed search. New private query UI MUST have
an explicit owner in the JJ family inventory. Source fingerprints MUST be
refreshed only after comparing the prior original layout and recording the
specific adaptation; review stops before Op Log work begins.

## AUI-GOV-001 — Source ownership

**Requirement.** Production packages MUST consume public Design Core primitives and injected host ports without application-private imports, credentials, native transports or catalog dependencies.

### Acceptance details

- Public Design Core exports MUST own shared filename artwork, while Agent/JJ components pass exact file paths and preserve semantic action/status icons.
- Focused tests and production-component stories verify the behavior.

## AUI-GOV-002 — Complete review

**Requirement.** Storybook MUST demonstrate complete production screens with isolated in-memory adapters and MUST NOT require live services. Consumer migration and publication MUST wait for explicit user review approval.

### Acceptance details

- Public types express the boundary.
- Building blocks and complete Agent/JJ screens MUST compose the same production implementations and host-owned controllers.
- Every named Empty or Unavailable story MUST expose visible public shadcn Empty content with an icon through the catalog-wide browser check.

## AUI-GOV-003 — Evidence

**Requirement.** Protected changes MUST update their owning contract and verification evidence. Functional and accessibility failures MUST remain explicit; visual baselines MUST NOT change without approval.

Specification validation MUST keep the Desktop transcript coverage inventory
complete, with existing production components and review stories for every mapped
renderer. It MUST reject missing mappings, components and catalog scenarios.
Source-package review archives MAY be used through an ignored, documented
validation overlay; published manifests and lockfiles MUST retain registry ranges.
An unpublished dependency's missing portable lockfile entries MUST remain an
explicit release prerequisite rather than a claimed frozen-install pass.
Clean package acceptance MUST compile documented examples for both packages
and exclude their catalog material; static catalog checks MUST audit both family
inventories and specification pages.
The development catalog MUST prebundle its actual icon/runtime dependencies,
retain strict compile/runtime diagnostics and qualify changed startup behavior
in a cold process.
Large shared-package chunks MUST pass the supported Vite asset-URL scanner;
catalog configuration MUST NOT disable its transforms or suppress import errors.

### Acceptance details

- Public types express the boundary.
- Focused tests and production-component stories verify the behavior.
