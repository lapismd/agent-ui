500-counted-line test budget; production and script files retain the 300-line
limit. This classification must not depend on the test runner.

the historical per-section stop boundaries below. Its five slices are authorized
for continuous implementation and focused commits, followed by required broader
qualification. Complete Storybook scenarios remain visual-pending. JJ Desktop
is the authorized consumer; publication and installed-app replacement are excluded.

## AUI-GOV-001 — Source ownership

**Requirement.** Production packages MUST consume public Design Core primitives and injected host ports without application-private imports, credentials, native transports or catalog dependencies.

Consumer applications MUST mount the completed public screens described in
`docs/consumer-integration.md`, preserving their layout and interaction flow.
Hosts MUST supply adapters and controller lifetime instead of recreating those
views from primitives. Missing native capabilities MUST remain explicit; missing
generic extension points belong in the owning library. JJ Desktop is the first
explicitly authorized consumer, including source-adapted shared appearance and
settings presentation. Other adoption and publication remain separate decisions.

The user authorized Stacks and Workspace presentation after Branches. The new
families MUST copy the source canvas/lane/card/files/history geometry, reuse the
portable stack controller and share existing graph/diff primitives. Host-owned
navigation/actions and controller lifetime remain explicit; transfers, mutation
dialogs and forge transport wait for their separate slices and review.

The drag/drop review follow-up authorizes connecting the existing workspace drag
session and demonstrating transfers with an isolated in-memory preview/apply
adapter. Production components emit host commands only. Native execution,
full mutation dialogs, forge transport and downstream adoption remain deferred.

The next Stacks/Workspace alignment follow-up authorizes source-adapted PR
details, action bars, commit drafts and the detachable floating panel in this
repository. Host-owned exact data and action ports replace native forge and
notification services. Live forge transport and downstream adoption remain
separate review gates.

## AUI-GOV-003 — Evidence

**Requirement.** Protected changes MUST update their owning contract and verification evidence. Functional and accessibility failures MUST remain explicit; visual baselines MUST NOT change without approval.

Specification validation MUST keep the Desktop transcript coverage inventory
complete, with existing production components and review stories for every mapped
renderer. It MUST reject missing mappings, components and catalog scenarios.
Source-package review archives MAY be used through an ignored, documented
validation overlay; published manifests and lockfiles MUST retain registry ranges.
An unpublished dependency's missing portable lockfile entries MUST remain an
explicit release prerequisite rather than a claimed frozen-install pass.
Clean package acceptance MUST compile documented examples for both packages
and exclude their catalog material; static catalog checks MUST audit both family
inventories and specification pages.
The development catalog MUST prebundle its actual icon/runtime dependencies,
including the public FileTypeIcon, filter and query-help Alert subpaths plus the shared CodeMirror query runtime, through both the Storybook dev
`viteFinal` hook and Vitest configuration,
retain strict compile/runtime diagnostics and qualify changed startup behavior
in a cold process. Browser documentation checks MUST bring lazy Canvas previews
into view before verifying their production component bounds.
Filename icon qualification MUST include local catalog skills in the complete
screen, preserving the copied row geometry and explicit host navigation.
Geometry assertions MUST compare rendered source slots at the current browser
zoom while retaining the declared icon size preset.
Documentation table probes MUST target their owning section and retain complete
semantic row and variable checks without traversing nested transcript tables.
Cold browser startup MUST await a fail-closed client-compiler readiness probe
covering Transcript documentation, complete Agent screens and reference fixtures;
missing or failed imports MUST prevent readiness, and repair MUST permit retry.
Large shared-package chunks MUST pass the supported Vite asset-URL scanner;
catalog configuration MUST NOT disable its transforms or suppress import errors.
History diff qualification MUST exercise context reveal and hide in both
unified and split layouts in JJ Log and Op Log, including synchronized split
panes and opaque fold-row gutters during horizontal scrolling; a single-layout
pass cannot stand for both presentations. All-file collection qualification MUST
cover bounded continuation, repeated navigation, independent section disclosure,
per-file host menu identities and retained single-file gutter behavior in both
logs, using production controllers with isolated in-memory readers.
Collection selection MUST be verified as painted pixels on both side edges over
diff content in light and dark themes, with real pointer header hover; computed
outline declarations alone are insufficient. Header qualification MUST distinguish
complete host totals, unavailable totals and per-file counts, and prove that
comparison-wide and file-scoped actions retain their respective identities.
All-file surface qualification MUST verify flush column geometry and invariant
sticky-header paint over contrasting content backdrops in both logs and themes,
including focused headers and actual outer-column scrolling.
Diff-status typography checks MUST cover unavailable and binary content in both
complete logs, including text sizes and independence from the code font.
Log canvas qualification MUST exercise the trailing resize hint, pointer and
keyboard resizing of the final Diff column, and retained horizontal access in
small panes in both complete logs.
