## AUI-GOV-001 — Source ownership

**Requirement.** Production packages MUST consume public Design Core primitives and injected host ports without application-private imports, credentials, native transports or catalog dependencies.

Consumer applications MUST mount the completed public screens described in
`docs/consumer-integration.md`, preserving their layout and interaction flow.
Hosts MUST supply adapters and controller lifetime instead of recreating those
views from primitives. Public header/navigation visibility props permit outer
application composition without duplicate ancestry or contextual tabs; Stacks
also exposes local view-tab visibility while retaining its workspace/actions. Missing native capabilities MUST remain explicit; missing
generic extension points belong in the owning library. JJ Desktop is the first
explicitly authorized consumer, including source-adapted shared appearance and
settings presentation. Other adoption and package publication remain separate
decisions. The Storybook catalog MUST publish from `main` to
<https://lapismd.github.io/agent-ui/> through
`.github/workflows/publish-storybook-pages.yml`. The repository README MUST link
that catalog and the npm-publish and Pages workflows. npm package publication
MUST remain a separate trusted-publish decision. The authorized release cohort
MUST retain independent public package versions: its immutable
`v<agent-ui-version>` tag identifies both exact package versions from that
source. Publication MUST bind each tarball to its own declared version and
integrity, run behind the protected npm publisher, and finish with exact
registry-byte comparison, a clean installed-version check and npm signature
and provenance verification. The publish and registry-verification jobs MUST NOT
configure an npm auth token, so trusted publishing uses the GitHub OIDC identity.
A manual dispatch that packs again MUST reference the same immutable
source as its workflow. Retries MUST NOT replace an existing package version.
A dispatch MAY republish an immutable tag only by reusing that tag's already packed tarballs unchanged.
Normal validation MUST execute the actual workflow identity and artifact-manifest
steps against isolated fixtures, proving independent versions and rejecting
invalid source/tag/package identities and wrong-version artifacts without
network, credentials or real repository mutations.

The user authorized Stacks and Workspace presentation after Branches. The new
families MUST copy the source canvas/lane/card/files/history geometry, reuse the
portable stack controller and share existing graph/diff primitives. Host-owned
navigation/actions and controller lifetime remain explicit; transfers, mutation
dialogs and forge transport wait for their separate slices and review.

The drag/drop review follow-up authorizes connecting the existing workspace drag
session and demonstrating transfers with an isolated in-memory preview/apply
adapter. Production components emit host commands only. Native execution,
full mutation dialogs, forge transport and downstream adoption remain deferred.

The next Stacks/Workspace alignment follow-up authorizes source-adapted PR
details, action bars, commit drafts and the detachable floating panel in this
repository. Host-owned exact data and action ports replace native forge and
notification services. Live forge transport and downstream adoption remain
separate review gates.

## Portable local validation

Portable root scripts MUST default to bounded Docker execution with explicit
native selection and no automatic host fallback. Exact source and ancestry,
registry-frozen installation and explicit checksum-qualified archive projection
MUST remain distinguishable. Source-bearing audit archives MUST retain identical
public runtime payloads and be recorded separately from distribution artifacts.
Source/history guards reject private/model/cache
payloads, while the tracked public port example retains a verified schema.
Tool image and JavaScript dependency caches MUST have separate identities.
Workers MUST use an init reaper, drop capabilities, prove actual permission
denial and collect failure evidence before owned terminal-only cleanup.
Story composition MUST resolve actual rendered production components; unused
imports cannot satisfy ownership. Complete catalog families MUST register their
complete production screen roots; an arbitrary control is insufficient. Recovered
virtual reference rows MUST be visibly painted before recovery is accepted, and
the picker MUST dismiss through its normal keyboard interaction. Fatal Svelte diagnostics MUST retain their
origin and survive teardown without preventing cleanup. Both themes and
viewport modes stay mandatory; focused zero-case runs MUST fail. Native source
comparison, host integration, visual approval and publication remain separate.
Complete catalogs MUST bound browser lifetime with sequential native shards,
retain every case in all four modes, and reject duplicate, missing or inconsistent
case identities. Focused selectors MUST remain literal and failures MUST NOT retry.
See [local validation](../../docs/local-validation.md) for commands and scope.

## AUI-GOV-004 — Hosted verification

**Requirement.** Hosted verification MUST run the existing package, catalog, browser and specification lanes through a bounded Turbo task graph on separate runners, then report one `verify` result. `spec:check` MUST run on every hosted verification and MUST NOT be cached.

`test:storybook` and `test:browser` MUST run at the same time on hosted runners. Vitest browser mode uses API port 63315 and writes `.local/validation/storybook`; cold browser acceptance binds Storybook to port 7498 and writes `.local/catalog-browser`. The portable `storybook:check` lane MUST keep those commands sequential because one worker shares `node_modules/.vite` and the bounded CPU and memory budget. Root scripts MUST be Turbo root tasks (`//#`) so the package workspaces cannot satisfy them by skipping a missing script.

### Acceptance details

- `turbo.json` MUST enable signed remote caching that fails open, `futureFlags.longerSignatureKey`, a `CI` global environment, and loose environment mode so hosted tasks keep `AGENT_UI_VALIDATION_RUNTIME`.
- Default concurrency MUST be half the available processors capped at four, with a validated `TURBO_CONCURRENCY` override.
- Remote cache credentials MUST come from CI secrets and MUST NOT be logged.
- Workspace package, catalog, Storybook, test, script and specification inputs MUST invalidate root task caches.

## AUI-GOV-005 — Version pull requests

**Requirement.** Changesets MUST prepare bot-authored version pull requests from `main` using only contents and pull-request write permissions. Candidates MUST pass normal protected checks and receive explicit review before merge. Version preparation MUST NOT publish packages, create release tags or approve pull requests.

`.github/workflows/changesets.yml` uses the same GitHub-token action pattern as
the sibling repositories. When GitHub suppresses automatic checks for a token's
PR event, a maintainer dispatches `.github/workflows/check.yml` on the reviewed
candidate branch. Its existing seven lanes and aggregate `verify` remain
mandatory. The protected, immutable-tag npm publisher remains separate.

### Acceptance details

- Version changes MUST derive from committed Changesets, preserve independent package versions and update the portable registry lock.
- The Changesets changelog setting MUST write each bumped package's `CHANGELOG.md`, which the version action reads before it opens the pull request.
- The reviewed bot branch MUST run the existing verification workflow; manual dispatch MAY start the same checks when token PR events are suppressed.
- Merging the version PR MUST leave actual npm publication to the protected immutable-tag publisher.
